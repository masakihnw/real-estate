# スクレイピングツール実装可否の検討

参照 [10年住み替え前提の中古マンション購入条件（ドラフト）](../../docs/10year-index-mansion-conditions-draft.md)

各サイトの利用規約の確認結果は [terms-check.md](./terms-check.md) にある。SUUMO、at home、HOME'S、REINSの規約と、スクレイピングの可否を整理している。

---

## 1. 条件ドキュメントで求められる情報

条件ドキュメントの判定フローとMust/Prefer条件から、ツールが扱うべき情報をデータソース別に整理する。

| カテゴリ | 条件 | 必要となる情報 | 主なデータソース |
|----------|------|----------------|------------------|
| 立地 | 駅徒歩5分以内（上限10分） | 最寄駅・徒歩分数 | 物件サイト（一覧・詳細） |
| 立地 | 主要ターミナルへのアクセス | 駅名・路線・所要時間 | 物件サイト、乗換案内系 |
| 立地 | 賃貸需要も強い | 周辺相場・入居率等 | レポートサイト、別データ |
| 耐震・築年 | 新耐震（1981年6月以降） | 築年・竣工年 | 物件サイト |
| 耐震・築年 | Prefer 築20年以内 | 築年 | 物件サイト |
| 管理・修繕 | 長期修繕計画がある | 計画の有無・内容 | 管理組合資料（非公開が多い） |
| 管理・修繕 | 修繕積立金が現実的 | 積立金・一時金計画 | 同上 |
| 管理・修繕 | 大規模修繕の実施・次回・積立残高 | 修繕履歴・残高 | 同上 |
| 管理・修繕 | Prefer 管理計画認定制度 | 認定の有無 | 国交省サイト・物件サイト（記載ある場合） |
| 建物スケール | 総戸数50戸以上（できれば100戸以上） | 総戸数 | 物件サイト（詳細に記載あり） |
| 売りやすい型 | 専有55〜75㎡、2LDK〜3LDK | 専有面積・間取り | 物件サイト |
| 成約・相場 | REINS成約で回転・価格推移を確認 | 成約価格・成約日・物件名 | REINS取引情報提供サイト |

## 2. データソース別のスクレイピング・API利用の可否

### 2.1 物件一覧・詳細（SUUMO / at home / HOME'S 等）

| 項目 | 可否 | 備考 |
|------|------|------|
| スクレイピング | 技術的には可能。利用規約の確認が必要 | 公開APIはない。過度なアクセスは規約違反やブロックのリスクがある。ポリシーに合わせた間隔とUAの配慮が前提。 |
| 取得しやすい項目 | 可 | 駅徒歩・築年・専有面積・間取り・価格・総戸数・最寄駅・路線名など。条件の一次フィルタに十分。 |
| 取得しづらい項目 | 一部可 | 長期修繕計画の有無・積立金・管理計画認定は、詳細欄にたまたま書いてある場合は取れる。原則は書類で確認する前提。 |

結論は次のとおり。

- 一次フィルタ用のツールは実装できる。
- 駅徒歩・築年・専有面積・間取り・総戸数・価格帯でMustの大半を絞り込み、候補20件を拾う用途に使える。
- 利用規約を確認したうえで、負荷を抑えた設計（リクエスト間隔、キャッシュ、利用を止められた場合の代替手段）が必須である。

---

### 2.2 REINS取引価格情報（成約データ）

| 項目 | 可否 | 備考 |
|------|------|------|
| 個人の利用 | 可 | 不動産取引情報提供サイト（レインズマーケットインフォメーション） `https://www.contract.reins.or.jp/` で、個人が無料で検索できる。 |
| スクレイピング・API | 要確認 | 画面上の検索結果のスクレイピングは技術的には可能。利用規約と利用目的の制限の有無を確認する必要がある。 |
| 得られる情報 | 成約中心 | エリア・築年数・間取り・最寄駅・取引時期などで絞り込み、成約価格と成約時期の傾向を把握できる。 |

結論は次のとおり。

- 成約データを取得できるかは、サイトの利用規約による。
- 規約が許容していれば、同一または近傍マンションの成約推移と回転の速さを補助するツールを実装できる。
- 規約が禁止している場合は、REINSを手動で確認する前提とする。物件サイトで拾った候補リストをREINS検索に渡すフローにするのが現実的である。

---

### 2.3 管理・修繕（長期修繕計画・積立金・認定制度）

| 項目 | 可否 | 備考 |
|------|------|------|
| 長期修繕計画・積立金 | 困難 | 管理組合の書類であり、物件サイトに載らないことが多い。中古の場合、購入検討時に売主や仲介から入手する前提。 |
| 管理計画認定 | 一部可 | 国交省のマンション管理計画認定制度の一覧等にリストはあるが、物件と突き合わせるには別途データ整備が必要。物件詳細に認定マンションと記載があれば、その物件に限り取得できる。 |

結論として、管理・修繕に関する自動収集は、補助的に拾える範囲にとどめるのが現実的である。ツールの主目的は、書類で10件に絞る前段の候補20件を効率的に出すことにある。管理書類の精査は、フロー上は手動のままとするのが妥当である。

---

### 2.4 マクロ・相場（国交省指数・東京カンテイ等）

| 項目 | 可否 | 備考 |
|------|------|------|
| 国交省 不動産価格指数 | 要確認 | 公開PDFとHTMLの取得は可能。利用規約と二次利用の可否を確認する必要がある。 |
| 東京カンテイ等のレポート | 要確認 | 有料・会員制の部分が多く、スクレイピング対象としての扱いは各社の規約による。 |

結論として、ツールのコア機能にはせず、参照用リンクや手動で見る前提にする。まずは物件フィルタとREINS補助に集中するのが安全である。

## 3. 実装可否の総合評価

### 3.1 実装できる範囲（推奨スコープ）

1. 物件サイトのスクレイピング（一次フィルタ用）
   - 条件ドキュメントの次のMustを、一覧と詳細から機械的に絞り込む。
     - 駅徒歩5分以内（上限10分）
     - 新耐震（1982年以降竣工を目安にした築年フィルタ）
     - 専有面積55〜75㎡
     - 間取り2LDK〜3LDK
     - 総戸数50戸以上
     - 価格帯7,500万〜1億円（必要なら変更できるパラメータ）
   - 対象サイトはSUUMO、at home、HOME'Sのいずれか、または複数（規約確認のうえ）。
   - 出力例として、条件を満たす物件のリスト（URL、主要項目、簡単なスコア）をCSVかJSONで保存する。これにより、候補20件を素早く拾えるようにする。

2. REINS取引情報の補助利用（規約確認後）
   - 規約が認めていれば、指定エリア・築年・間取り等で成約傾向を取得する。回転の速さと価格推移の参考データは、ツール側で表示する。
   - 認められていなければ、物件ツールの出力（候補マンション名・駅・築年）を、チェックリストとして使う。このチェックリストは、REINSの検索条件を手動入力するためのものである。

3. 判定フローとの対応
   - 条件ドキュメントの「1. 物件候補を20件拾う」を自動化する部分を、ツールが担当する。
   - 「2. 管理書類で10件に絞る」「3. REINS成約で最終3件」「4. 内見」は、手動フローとして残す。この手動フローは、ツールの出力を入力にする。

### 3.2 実装が難しい、または見送る方がよい範囲

- 長期修繕計画・積立金・大規模修繕履歴の自動取得は、データが物件サイトに揃っておらず、スクレイピングでは現実的でない。
- 賃貸需要の定量的な自動判定は、別データや別サービスが必要で、スコープが大きくなりがちである。
- 国交省指数・東京カンテイ等の自動取り込みは、規約と利用形態の確認が重いため、初版ではリンク集と手動参照にとどめる。

### 3.3 技術的な注意点

- 利用規約の確認として、SUUMO / at home / HOME'S / REINS取引情報サイトの利用規約を読む。クローラー行為と商業利用の可否を必ず確認する。
- 負荷対策として、リクエスト間隔（例 1〜2秒以上）、User-Agentの明示、必要に応じたキャッシュを入れる。
- 運用では、サイト構造の変更で取得できなくなるリスクがある。重要な判断は、ツール結果と手動確認の二段構えにする。

## 4. 次のステップ案

1. 規約確認。結果は [terms-check.md](./terms-check.md) に整理済みである。
   - SUUMOは、私的利用と軽負荷にとどめれば許容の余地がある。
   - at homeは、クローラー等による情報取得が明示的に禁止されているため、対象外を推奨する。
   - HOME'Sは、明示的な禁止はないが、妨害・営利・第三者提供に当たりうる。
   - REINSは、規約の所在と内容を要確認とした。
2. プロトタイプの対象を1サイトに限定する。
   - 規約リスクを考慮し、SUUMOを第一候補とする。at homeはスクレイピング対象から外す。
   - まずSUUMOで上記の一次フィルタ項目を取得する最小スクリプトを作り、出力形式（CSV/JSON）と項目を固める。
   - 現状の物件一覧スクレイパー（`*_scraper.py`）は、SUUMO、HOME'S、at home、ノムコム、三井のリハウス、東急リバブル、ステップ（住友不動産販売）の7つである。at homeとステップは、`config.py` の `DISABLED_SCRAPERS` で無効にしている。at homeを無効にした理由は、GitHub ActionsのIPがbot判定を受け、全区で0件になるためである。
3. 判定フローとの接続。出力を候補20件リストとして使う手順を、条件ドキュメントの判定フローに追記する。
4. REINSの扱いを確定する。規約確認後に、自動取得するか、手動検索用の入力リスト機能にとどめるかを決める。現状、`scraping-tool` のPythonコードにREINSを取得する処理はない。

## 5. まとめ

| 質問 | 回答 |
|------|------|
| 条件を満たす物件を探すスクレイピングツールは実装できるか | 実装できる。条件のすべてを自動判定するのではなく、駅徒歩・築年・専有・間取り・戸数・価格など、物件サイトに載っている項目で一次フィルタし、候補20件を効率的に出すツールとして実装する。 |
| どこまで自動化し、どこを手動にするか | 自動化は、一次フィルタ（上記項目）による物件候補の収集とリスト化である。手動のまま残すのは、管理書類による絞り込み、REINSでの成約確認、内見である。REINSは規約次第で、補助的に自動取得できる。 |
| フォルダ整理後の役割 | `docs/` に条件と相談メモを置き、`scraping-tool/` に一次フィルタ用スクレイピングの設計・実装・運用メモをまとめる。この構成で、実装可能性とスコープを両立できる。 |

以上から、一次フィルタ用の物件スクレイピングツールは実装できる。条件ドキュメントの判定フローの第1ステップを効率化する目的で進めることは妥当と判断する。
