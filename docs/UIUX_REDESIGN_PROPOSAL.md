## 0. 前提とゴール

本提案は、次のゴールに向けた現状調査（コードベース全数調査）、刷新案、追加機能提案である。

| ゴール | 本提案での解釈 |
|---|---|
| 必要なタイミングで必要な情報 | 利用シーンを「①朝晩の新着・値下げチェック」「②暇つぶし探索」「③腰を据えた検討」「④現地内見」の4モードに分け、各モードで最短経路を設計する |
| 毎日触りたくなるデザインと体験 | 「今日の動き」を中心にしたホーム刷新とスワイプ探索の強化。モーションとハプティクスで操作の気持ちよさを作る |
| 毎日触ってもストレスにならない快適性 | スクロール量・タップ数・待ち時間の削減を数値目標で管理する（§2.3 のKPI） |
| 開発途中の画面がない | 開発者向け機能の隔離、デッドコードの削除、データ欠損時の見せ方の統一 |
| 情報のメリハリ | 各画面で最重要の1情報を定義し、それ以外は段階的開示（progressive disclosure）に回す |

確認済みの前提として、本アプリは自分（家族）専用ツールである。汎用プロダクト向けのオンボーディング強化は不要で、個人前提だから許される最適化を伸ばす。最適化の例は、buyer_profile との直結、通勤先の固定、判断基準の単一化である。デザイン方向はハイブリッドとし、発見は写真を中心に、検討はデータを中心に構成する。

## 1. 現状調査サマリー

### 1.1 アプリ構造（情報アーキテクチャ）

提案時点は6タブ構成だった（`ContentView.swift`）。

| タブ | 内容 | 日次利用での役割 |
|---|---|---|
| ダッシュボード | 統計・スワイプ導線・タイムライン等 9セクション | 毎日の起点（だが情報過多） |
| 物件 | 中古一覧＋フィルタ＋比較 | 検討の中心 |
| 地図 | 物件ピン＋ハザード10レイヤー | 補助的 |
| マイリスト | お気に入り一覧（物件タブと同一View） | 検討の中心 |
| 成約 | 成約事例の一覧/地図 | 参照頻度低（検討時のみ） |
| 設定 | 通知・データ・My指標・開発者ツール・アカウント | 稀 |

主要な構造的課題は次のとおり。

- ダッシュボードが9セクション・2〜3画面分あった（`DashboardView.swift` 1,014行）。「今日の変化を30秒で確認」したいのに、次の項目が一列に並んでいた。並んでいたのは、統計カード、スワイプ、クイックフィルタ、AI、スコア分布、タイムライン、ウォッチ値下げ、価格変動、エリアランキングである。毎日見る情報（新着・値下げ）とたまに見る情報（スコア分布・エリアランキング）が同じ重みで混在していた。
- 「物件」と「マイリスト」が同一Viewの引数違いで、タブとしての役割分担が曖昧だった。
- 「成約」が独立タブだった。成約事例は単体で眺める情報ではなく、「この物件は相場と比べてどうか」を知る文脈で必要になる情報である。独立タブにしたことで、限られたタブの枠を成約に1つ使っていた。
- `NopedListingsView.swift` がどこからも到達できないデッドコードだった（Nopeの解除手段がUI上に存在しなかった）。
- 開発者向け機能がユーザー動線に混在していた。設定 > 詳細設定に「スクレイピング条件」「スクレイピングログ」「Supabase APIトグル」「カスタムURL」があった。
このアプリについてにも「診断情報」があった。これらはゴール「必要なものだけが表示される」に反していた。

### 1.2 主要画面のUX課題（定量）

| 画面 | 計測値 | 課題 |

### 1.3 ビジュアルデザインの現状（デザインシステム監査）

`Design/DesignSystem.swift` には、セマンティックカラー（スコアS〜D、AI accent、価格上下、ソース別色等）が定義済みだった。しかし採用率は極端に低かった。

| 項目 | 実態 |
|---|---|
| 色 | ハードコード色が394箇所（45ファイル）。不透明度は 0.04〜0.9 の12段階がアドホックに散在。トークン採用率は5%未満 |
| タイポグラフィ | フォント指定832箇所のうちデザイントークン（`ListingObjectStyle`）の使用は11箇所（1.3%）。`.system(size: 8〜13)` のハードコードが37箇所以上（Dynamic Type非対応） |
| 角丸 | トークンは12だが、実際は `cornerRadius: 8` が49箇所で最多。3/4/5/6/8/10/12/14/20 が混在 |
| 余白 | トークンは4つのみ。`.padding(14)` が23箇所など、20種以上のマジックナンバー |
| 影 | トークンなし。6種類の組み合わせが各Viewで独自定義 |
| ハプティクス | 0箇所（スワイプのLike/Nopeにすら無い） |
| ダークモード | セマンティックカラー経由で概ね対応。LoginViewの青グラデ等のハードコード箇所は未検証。Assets.xcassetsにカスタム色なし（AccentColor空） |
| コンポーネント | ScoreBadge/HighlightBadgeView等は共通化済みだが、カード・行・バッジ・価格フォーマットは画面ごとに再実装されていた（DashboardだけでStatCard/PriceMoverRow/TimelineFeedRow/WatchlistPriceDropRowが別実装） |
| アクセシビリティ | 67箇所（11ファイル）に偏在。チャートと色のみのバッジは読み上げ不可 |

デザインシステムはあるが、採用率が極端に低く、機能していなかった。刷新の第一歩は、ビジュアルの方向性を決める前に、トークンの拡充と強制（lint）を行うことである。

### 1.4 データ資産の棚卸し（提案の材料）

このアプリの最大の強みは、個人用のアプリとしては例外的に多くの種類のデータを持つことである。次のデータを持つ。
AIスコアリング（5軸）、AI推奨（1〜5点＋フラグ＋ネクストアクション）、住まいサーフィン（沖式・ランキング・5/10年シミュレーション）、成約事例（reinfolib）、ハザード（GSI 10種）。
通勤時間（2社分）、人口動態（e-Stat）、価格履歴、重複検知も持つ。

一方、取得済みなのにUIに出ていない、または活かせていないデータが多数あった。

| データ | 現状 | 活用余地 |
|---|---|---|
| マンションレビュー（管理品質） | 取得済み・非表示 | 詳細の「建物」評価、比較表の行 |
| 周辺施設スコア（Google Places: 学校・店・公園） | 取得可能・UIなし | 家族向けに価値大 |
| 用途地域 `zoning` | フィールド有・非表示 | 将来の眺望・環境リスク判断 |
| 長期修繕情報（AI抽出） | 抽出済み・非表示 | 資金計画 |
| 同建物の住戸別価格判定 `ssPriceJudgments` | 詳細にリスト表示のみ | 「この建物ならどの住戸が買いか」 |
| ローン残高予測 `ssLoanBalance5yr/10yr` | 表示のみ | 売却シミュレーション（残債割れ判定）に組み込む |
| feature_tags | リスト表示のみ | フィルタ・推薦に未使用 |
| 賃料相場・利回り | 未取得 | 出口戦略の説得力向上（新規データ） |

## 2. 刷新コンセプト

### 2.1 4つの利用モードと「必要なタイミングで必要な情報」

| モード | 頻度 | 滞在時間 | 中心になる情報 | デザイン |
|---|---|---|---|---|
| ① 今日のチェック | 毎日 朝晩 | 30秒〜2分 | 新着・値下げ・ウォッチ物件の変化 | 変化を中心に表示する。変わったものだけ見せる |
| ② 暇つぶし探索 | 毎日 隙間時間 | 2〜10分 | 物件写真・直感的な好み | 写真を中心にした全画面のスワイプ |
| ③ 腰を据えた検討 | 週末 | 10分〜 | AI分析・相場・シミュレーション | データを中心にした高密度の比較表示 |
| ④ 現地内見 | 不定期 | 現地で | チェックリスト・メモ・周辺相場 | 片手操作・オフライン耐性 |

提案時点のアプリは③に全面的に寄った作りで、①②は③の画面の中に置かれていた。刷新の中心は、①②を③と同格の独立した画面にすることである。

### 2.2 デザイン原則（5箇条）

1. 1画面1ヒーロー。各画面で一番伝える情報を1つ決め、面積・タイポ・色のコントラストをそこに集中させる。それ以外は段階的開示に回す。
2. 変化を目立たせる。毎日触る理由は変化である。新着・値下げ・順位変動を、色とモーションで最初に目に入るようにする。変化がない日は「変化なし」を1行で伝え、すぐ②に誘導する。
3. 発見には写真、判断にはデータを使う。発見系画面（Today・スワイプ・一覧カード）は写真とAIバッジを使い、検討系画面（詳細・比較）は数値とチャートを使う。同じ物件オブジェクトでも、画面のモードで表現を切り替える（OOUIの徹底）。
4. 判断の言語はS〜Dグレードにする。AIスコア・沖式・価格妥当性など多数の指標を、最初に見る場所では「グレード＋一言」に集約し、内訳はタップで開く。
5. 操作に触覚と動きを付ける。全主要操作にハプティクス、状態変化にスプリングモーションを付ける。iOS 26 Liquid Glass を全面採用し、フォールバックを維持する。

### 2.3 快適性のKPI（刷新の合格基準）

- 朝のチェック完了（新着＋値下げ＋ウォッチ確認）は、アプリ起動から30秒以内・スクロール1画面以内
- 一覧から詳細に進んだ「買い/見送りの一次判断」は、詳細1画面目（スクロールなし）で完結
- お金シミュレーションへの到達は、詳細から1タップ
- ソート変更は2タップ・選択肢は1階層8択以内（残りはグループ内）
- スワイプは中断から再開しても進捗を保持

## 3. 情報アーキテクチャ刷新案

### 3.1 タブ再編: 6タブ から 4タブ

```
現在:  ダッシュボード | 物件 | 地図 | マイリスト | 成約 | 設定
提案:  今日 (Today)   | さがす (Browse) | マイリスト (Library) | 設定
```

| 新タブ | 統合される既存機能 | 役割 |
|---|---|---|
| 今日 | ダッシュボード（再設計）＋スワイプ導線 | モード①②の起点。デイリーダイジェスト |
| さがす | 物件一覧＋地図（リスト/マップをセグメントで切替）＋フィルタ | モード③の入口。成約事例は地図レイヤーと詳細セクションに移す |
| マイリスト | お気に入り＋比較＋最近見た＋Nope管理＋内見予定 | 自分の検討状況のホーム。WatchlistViewもここに統合 |
| 設定 | 通知・My指標・通勤先・買付準備 | 開発者機能は隔離する（§3.7） |

理由は次のとおり。

- 「物件」と「マイリスト」は同一Viewである。タブを分けるより、検討ステータス（未評価/気になる/見送り）で分ける方が、利用者の考え方に合う。
- 「成約」タブには利用文脈がない。成約データは次の3か所に分けて表示する。(a) さがす地図の「成約価格レイヤー」（ハザードと同列のレイヤー）、(b) 物件詳細の相場セクション、(c) 新設の「相場レポート」（Todayの週次カード）である。
- 地図はリストと同じ「さがす」行為の表示形式違いである。Zillow/SUUMOと同様に、リストとマップのトグルが自然である。フィルタ状態も共有でき、リストとマップでフィルタを別管理していた問題も解消する。

### 3.2 「今日」タブ（新ホーム）の設計

毎日のチェックを最短化する朝刊型の構成にする。上から次の順に並べる。

1. ヘッダーにAIデイリーブリーフを置く。「新着3件。うち1件は予算内・S評価。広尾の気になる物件が▲200万円」のように1〜2文で伝える。変化ゼロの日は「今日は動きなし。新着スワイプが5件待っています」とする。
2. 変化カードを横スクロールで最大5枚並べる。新着/値下げ/再掲載/ウォッチ変動を、1枚=1物件の写真カードにする。タップで詳細、長押しでクイックアクション（お気に入り/Nope/共有）を開く。
3. スワイプ入口を置く。未評価が残っていれば、大きめのカードで「未評価12件をスワイプ」と出す。
4. 今週の相場を、週1更新の折りたたみカードにする。エリアランキング・スコア分布・成約トレンドをここに集約し、毎日は見せない。
5. タイムライン全文などは「すべての動きを見る」リンクの先に置く。

現在9セクションが常時並ぶ構成を、毎日変わるもの3つと週次1つに圧縮する。

### 3.3 物件詳細の再設計（最重要）

25セクションの縦一列を、1画面目で判断し、タブで詳細を見る構成に変える。

1画面目（ヒーローカード）は、スクロールせずに一次判断が完結する構成にする。

- 写真ギャラリー（ページング、カテゴリチップ: 外観/室内/間取り）
- 物件名・価格（変動があれば旧価格の打ち消し線と▲X%バッジ）
- AI判定ストリップ。グレードバッジ（S〜D）、推奨度（1〜5点）、一言サマリー、フラグチップ（「駅近◎ 築浅 手狭リスク」など）を並べる
- KPIストリップ。月額支払い、駅徒歩、広さ、通勤時間（2社）を並べる
- 主アクション。お気に入り保存、共有、元サイトを置く

2画面目以降は、上部に固定する5つのセクションタブ（ピン留めセグメント）にする。

| タブ | 統合する既存セクション |
|---|---|
| 概要 | 物件スペック・AI抽出特徴・別ソース価格・重複候補 |
| お金 | 月額シミュレーション＋統合シミュレーター（現5ツールを1画面に。下記） |
| 資産性 | 沖式・レーダー・5/10年シミュレーション・成約事例・市場比較・同建物住戸判定・人口動態 |
| 環境 | 通勤・ハザード・周辺施設（新規）・用途地域（新規表示）・マンションレビュー（新規表示） |
| メモ | コメント・内見チェックリスト・内見写真・AI相談（Markdownコピー） |

- セクションタブは `safeAreaInset` で上部に固定し、現在地を常に表示する（既存のセクションナビを置き換える）。
- お金ツールは、月額/諸費用/減税/銀行比較/賃貸vs購入/リノベの6ツールを、単一シミュレーターに統合する。このシミュレーターは前提条件（価格・金利・期間・頭金）を1箇所で共有する。タブを切り替えると結果ビューだけが変わる。現状のツール間で金利を二重入力する問題と、アイコンだけのボタンが6つ並ぶ問題を解消する。
- データ未取得のセクションは、見出しだけ薄く出す現状をやめる。セクションを非表示にし、概要タブの末尾に「未取得: 沖式・レビュー」と1行で表記する（開発途中に見える状態の排除）。

### 3.4 さがす（一覧・フィルタ・地図）

- ソートは48択から、8つの代表ソートと「詳細ソート」に変える。代表は新着順 / 価格 / 価格の割安度 / 総合スコア / AI推奨 / 駅近 / 広さ / My指標とする。詳細ソートは、基本・立地・お金・資産性・AIにグループ化したピッカーに入れる。
- 保存フィルタ（検索条件）を標準機能にする。検索バーの下に、「予算内S評価」「広尾エリア」などの保存条件をチップで並べ、1タップで適用する。新着がその条件にヒットしたらチップにバッジを付ける。FilterStoreは既存なので、拡張で対応できる。
- 数値フィルタにデータ充足率を表示し（「沖式儲かる確率 (データあり 62%)」）、0件になる操作を予防する。
- 駅ピッカーは検索フィールドを先頭に置く。3階層のドリルダウンは補助として残す。
- 地図のピンのコールアウトに「グレード・価格・徒歩・ハザードアイコン」を追加し、詳細を開かずに一次判断できるようにする。ハザードレイヤーは、よく使う2つ（洪水・地震リスク）をワンタップのトグルにし、残りはシートに入れる。成約価格はヒートマップレイヤーとして追加する。

### 3.5 スワイプ（暇つぶし探索の中心）

- 進捗を永続化する。途中で離脱したらデッキ位置を保存し、次回は続きから始める。
- ハプティクスとスタンプを付ける。Like/Nopeで `sensoryFeedback` を発火し、ボタン操作でもスタンプアニメーションを表示する。
- デッキを拡張する。現在は「画像つき新着」だけである。「S/Aだけ」「予算内だけ」「保存フィルタ◯◯」の条件付きデッキを選べるようにする。新着が尽きても、過去の未評価物件を再配給して暇つぶしが成立するようにする。
- カードから詳細を見られるようにする。上スワイプまたはタップで「ミニ詳細」（ヒーローカード相当）をその場に展開し、戻ってスワイプを続ける。
- Skipの意味を「あとで」（次回デッキの先頭に再登場）と明示する。
- 未接続の `NopedListingsView` を、マイリストの「見送り」タブとして接続し、一括解除を追加する。

### 3.6 マイリスト（検討のホーム）

- セグメントは「気になる（お気に入り） / 比較中 / 見送り / 最近見た」とする。
- 気になる一覧は、価格変動があったものを最上部に自動ソートする（WatchlistViewの値下げセクションを統合）。
- 比較はカード2枚を並べる形（縦持ちで2物件、項目は行スワイプで送る）に再設計し、横スクロールグリッドを廃止する。差分が大きい行を自動でハイライトする（既存の `ComparisonHighlight` を使う）。
- 内見予定の物件には「内見モード」バッジを付ける（§5 の6）。

### 3.7 開発者機能の隔離と「必要なものだけ」

- スクレイピング条件 / スクレイピングログ / Supabaseトグル / カスタムURL / 診断情報を、設定末尾の「開発者」セクションに移す。
このセクションは、バージョン番号を7回タップすると出現し、UserDefaultsで永続する。普段の設定画面からは消す。
- `NopedListingsView` は §3.5 のとおり正式に接続し、デッドコードを解消する。
- 設定の「買付準備」「通勤先設定」は詳細設定から昇格させ、買付準備はマイリストからも到達できるようにする。
- ウォークスルー（7ページ）は自分専用アプリでは過剰である。設定のヘルプに残すだけとし、初回の自動表示は廃止する。

## 4. デザインシステム刷新

### 4.1 トークン体系の拡充（DesignSystem.swift v2）

```swift
enum DS {
    enum Spacing { // 4pt グリッド
        static let xs: CGFloat = 4; static let sm: CGFloat = 8
        static let md: CGFloat = 12; static let lg: CGFloat = 16
        static let xl: CGFloat = 24; static let xxl: CGFloat = 32
    }
    enum Radius {
        static let chip: CGFloat = 8      // バッジ・チップ
        static let card: CGFloat = 16     // カード（現12から拡大、Liquid Glass映え）
        static let sheet: CGFloat = 24    // モーダル上端
    }
    enum Opacity {
        static let tintBg = 0.08; static let border = 0.16
        static let disabled = 0.4; static let overlay = 0.6
    }
    enum Shadow { // 2種のみに統一
        static let card = ShadowStyle(opacity: 0.08, radius: 8, y: 4)
        static let floating = ShadowStyle(opacity: 0.16, radius: 16, y: 8)
    }
    enum Typography { // Dynamic Type 対応の役割ベース
        static let hero = Font.largeTitle.bold()          // 価格など最も目立たせる数値
        static let sectionTitle = Font.headline
        static let body = Font.subheadline
        static let label = Font.caption
        static let badge = Font.caption2.weight(.semibold)
        // .system(size:) の新規使用は禁止
    }
}
```

- 既存のセマンティック色（スコア・価格上下・AI・ソース・ハザード）をAssets.xcassetsのカラーセットに移す。あわせてダーク用バリアントを定義する（現在カタログは空）。
- アクセントカラーを定義する（提案は、信頼感のある deep teal 系と、AI用に維持する indigo）。ブランドの軸を作る。
- 段階導入を強制する。`swiftlint` のカスタムルール（またはCIのgrep）で、`Color(red:` / `.system(size:` / `cornerRadius: [0-9]` の新規追加を警告する。既存394箇所は、画面刷新と同時に置き換える。

### 4.2 コンポーネントライブラリ

最低限そろえる共通部品を次に示す。既存の良い部品は昇格させる。

| コンポーネント | 置換対象 |
|---|---|
| `ListingCard`（写真中心・Today/スワイプ/一覧グリッド用） | DashboardのStatCard/PriceMoverRow等4種の独自実装 |
| `ListingRow`（リスト用・現行ベース） | ListingListView内のセル |
| `MetricChip` / `DeltaBadge`（±変化表示の統一） | 価格バッジ各所 |
| `SectionCard`（見出し＋折りたたみ＋Glass背景） | 詳細25セクションの台紙 |
| `GradeBadge`（ScoreBadgeを拡張、アクセシビリティラベル必須） | 既存ScoreBadge |
| `PriceText`（priceDisplay系をView化、フォーマッタ一元化） | formatYenCompact等の重複実装 |

### 4.3 モーション＆ハプティクス指針

- ハプティクスは、現状ゼロから標準装備にする。Like/Nope = `.impact(.medium)`、保存・適用 = `.success`、値下げ発見カードの表示 = `.soft` とする。`sensoryFeedback` modifier（iOS 17+）で統一して実装する。
- モーションの標準は `.spring(response: 0.35, dampingFraction: 0.8)` に統一する（現在は 0.2/0.25/0.3/0.35 が混在）。カードの出現はスタッガード（0.05s刻み）、価格変動の数値はカウントアップにする。全アニメーションで `reduceMotion` 対応を義務にする（現在は1箇所のみ）。
- 一覧から詳細への画面遷移は、写真の `matchedGeometryEffect` で行う。NavigationTransition `.zoom`（iOS 18+）を使う。写真がそのまま開く体験にする。

### 4.4 アクセシビリティ最低ライン

- チャート（レーダー・シミュレーション）に、`accessibilityLabel` で要約文（「総合評価は6軸中4軸でエリア平均超え」）を付ける。
- 色だけで意味を伝えている箇所（グレード・ハザード・価格上下）に、記号またはテキストを併記する。
- `.lineLimit(1)` の箇所で Dynamic Type を検証する。ハードコードサイズを全廃すれば、大部分は自動で解決する。

## 5. 追加機能の提案

データ資産調査（§1.4）に基づく。毎日触る理由を作る機能を上位に置く。

### P1（刷新と同時に入れたい）

1. AIデイリーブリーフ（§3.2）。既存のAI enrichmentパイプラインに「日次サマリー生成」を1モジュール追加する（`config/prompts/daily_brief.md`）。新着・価格変動・ウォッチ変化を1〜2文に要約してSupabaseに置く。Todayヘッダー、プッシュ通知、ウィジェットがこの要約を共用する。通知が「新着3件」から「予算内のS評価が広尾に出ました」に変わり、毎日開く動機になる。
2. 保存フィルタと条件マッチ通知（§3.4）。「この条件の新着だけ知りたい」を実現する。既存のFilterStoreと通知基盤を拡張する。
3. スワイプ進捗の永続化と条件付きデッキ（§3.5）。
4. ウィジェット刷新。現在の件数表示から「今日の1枚」（変化カード先頭の物件写真＋価格変動）に変える。スモールは1物件、ミディアムはブリーフ1文と2物件にする。タップで該当詳細にディープリンクする（基盤あり）。
5. 未活用データの表示（実装コスト極小）。マンションレビュー・用途地域・長期修繕・周辺施設スコアを、詳細の「環境」「資産性」タブに表示する。

### P2（次フェーズ）

6. 内見モード。マイリストの物件を「内見予定」にすると、当日は現地向けレイアウトを1画面に出す。レイアウトの内容はチェックリスト・写真撮影・メモ・周辺成約価格・ハザードである。既存のchecklistJSONと内見写真機能を再パッケージする。
7. 売却出口シミュレーター。`ssSimBest/Std/Worst` と `ssLoanBalance` を組み合わせる。「X年後に売ると残債±いくら」を1チャートに表示する（データは取得済みで、計算とUIのみ）。
8. 同建物の買い時ガイド。`ssPriceJudgments`（住戸別判定）を「この建物で一番割安な住戸」カードに昇格する。`duplicateCount` / `competingListingsCount` と組み合わせ、「売り急ぎシグナル」を表示する。
9. 家族コラボの強化。既存のコメント機能に、夫婦それぞれの星評価を追加し、比較画面に「ふたりの一致度」を表示する。自分専用アプリの家族側の体験を作る。

### P3（将来・新規データ取得が必要）

10. 賃料相場と実質利回り。賃貸掲載のスクレイピングを追加し、「貸したら月いくら/表面利回り」を資産性タブに表示する。賃貸vs購入シミュレーターの精度も向上する。
11. 新耐震/旧耐震の自動判定と建替えリスク表示。builtYearから判定できる。表示だけならP1相当である。
12. 再開発・都市計画情報。東京都都市計画GISと突合する（用途地域表示の発展形）。

### 削除・縮小の提案（「必要なものだけ」）

- ダッシュボードのスコア分布・エリアランキングの常時表示を、週次カードに移す。
- 初回ウォークスルーの自動表示を廃止する。
- CSVエクスポートを、マイリストのメニュー内に格納する（ツールバーから撤去）。
- 通知頻度0〜6回/日を、プリセット（朝 / 朝晩 / リアルタイムのみ）に簡素化する。
